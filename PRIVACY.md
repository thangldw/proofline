# Privacy Policy

Last updated: 2026-08-24

## English

Proofline and its bundled plugin are local-first. The project operates no hosted Proofline service, creates no user accounts, collects no telemetry, and does not send sources, decisions, citations, evidence packages, local paths, or credentials to the project author.

User-selected sources, decisions, provenance metadata, derived indexes, and review state are stored in user-controlled local storage. Exports, reports, packages, attestations, and backups are written only to user-selected paths. Users control retention by managing the local data directory and exported files.

Private signing keys remain local. Proofline reads a private key only for an explicitly invoked signing command, does not store it in SQLite or plugin assets, and places only a public-key identifier and signature in an attestation envelope.

An optional model or embedding provider receives selected content only when a user configures and invokes it. That provider's terms apply. Proofline does not enable providers automatically or embed provider credentials.

Do not publish confidential material in support issues. For privacy questions, use [GitHub Issues](https://github.com/thangldw/proofline/issues); for suspected vulnerabilities, follow [Security](SECURITY.md). English controls if a translation conflicts.

## Tiếng Việt

Proofline và bundled plugin là local-first. Project không vận hành hosted Proofline service, không tạo user account, không thu telemetry và không gửi source, decision, citation, evidence package, local path hoặc credential cho tác giả project.

Source do người dùng chọn, decision, provenance metadata, derived index và review state được lưu trong local storage do người dùng kiểm soát. Export, report, package, attestation và backup chỉ được ghi vào path do người dùng chọn. Người dùng kiểm soát retention bằng cách quản lý local data directory và file đã export.

Private signing key giữ ở local. Proofline chỉ đọc private key khi người dùng gọi rõ signing command, không lưu key trong SQLite hoặc plugin asset và chỉ đặt public-key identifier cùng signature vào attestation envelope.

Model hoặc embedding provider tùy chọn chỉ nhận nội dung được chọn khi người dùng cấu hình và gọi provider đó. Điều khoản của provider được áp dụng. Proofline không tự bật provider và không nhúng provider credential.

Không đăng confidential material trong support issue. Với câu hỏi privacy, dùng [GitHub Issues](https://github.com/thangldw/proofline/issues); với vulnerability nghi ngờ, làm theo [Security](SECURITY.md). English có hiệu lực nếu bản dịch xung đột.

## 日本語

Proofline と bundled plugin は local-first です。Project は hosted Proofline service を運営せず、user account を作成せず、telemetry を収集せず、source、decision、citation、evidence package、local path、credential を project author に送信しません。

User が選択した source、decision、provenance metadata、derived index、review state は user-controlled local storage に保存されます。Export、report、package、attestation、backup は user が選択した path のみに書き込まれます。Retention は local data directory と export file の管理によって user が制御します。

任意の model または embedding provider は、user が設定して実行した場合だけ選択 content を受け取ります。その provider の規約が適用されます。Proofline は provider を自動的に有効化せず、provider credential を埋め込みません。

Confidential material を support issue に公開しないでください。Privacy の質問は [GitHub Issues](https://github.com/thangldw/proofline/issues)、vulnerability の疑いは [Security](SECURITY.md) に従ってください。翻訳が競合する場合は English を優先します。
