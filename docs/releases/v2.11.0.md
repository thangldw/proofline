# Proofline v2.11.0

Released: 2026-11-20

## English

### What shipped

- `proofline propose` drafts a candidate decision for a dependency or infrastructure file that no approved decision mentions (`--base origin/main`, or `--kind`, `--name`, `--path`). The draft is always `Status: candidate`, carries a TODO rationale and an inactive suggested `Enforce:` rule, and is never accepted for you. In Claude Code, `agent-hook post` now tells the agent when it adds such a file and asks it to offer a draft to you.
- `proofline attest-release` signs a content-free statement for the checked-out commit with the Ed25519 keys `attest` already uses: stale-citation count, `Enforce:` finding count, a digest of the approved decisions, the ledger head, whether tracked files were modified, and `compliant`. `proofline verify-release-attestation` checks it against a key you trust and, optionally, a commit. It is a new `proofline-release-attestation-v1` schema; existing attestations are unchanged.
- `proofline export-rules` turns `Enforce: forbid` rules into Semgrep rules, checked against a real Semgrep, so a team that already runs Semgrep enforces decisions in CI at scale.

```bash
python -m pip install proofline-evidence==2.11.0
```

### Compatibility and evidence limits

No schema migration, export format, evidence package or existing attestation change. A release attestation signs counts at one commit; it proves who signed which numbers, not that the rules or checks were sufficient, and it signs a failing state truthfully as `compliant: false` unless you pass `--require-compliant`. A key is never trusted from the file itself. `export-rules` exports `forbid` rules only: `require` and `require file` rules cannot be expressed as Semgrep matches, and every skipped rule is listed on stderr. The agent nudge covers edits of dependency manifests and whole-file writes of infrastructure files, matches names by whole word, and never accepts a proposal. `proofline mcp` is unchanged: read-only, and it does not authenticate callers.

## Tiếng Việt

### Nội dung phát hành

- `proofline propose` soạn decision ứng viên cho dependency hoặc file hạ tầng mà không decision đã duyệt nào nhắc tới (`--base origin/main`, hoặc `--kind`, `--name`, `--path`). Bản nháp luôn là `Status: candidate`, có lý do TODO và một luật `Enforce:` gợi ý chưa kích hoạt, và không bao giờ được tự duyệt thay bạn. Trong Claude Code, `agent-hook post` nay báo cho agent khi nó thêm file như vậy và yêu cầu agent đề nghị bản nháp với bạn.
- `proofline attest-release` ký một tuyên bố không chứa nội dung cho commit đang checkout, bằng chính khóa Ed25519 mà `attest` đã dùng: số citation stale, số phát hiện `Enforce:`, digest của các decision đã duyệt, đầu ledger, tracked file có bị sửa không, và `compliant`. `proofline verify-release-attestation` kiểm tra với khóa bạn tin cậy và tùy chọn một commit. Đây là schema mới `proofline-release-attestation-v1`; attestation hiện có không đổi.
- `proofline export-rules` biến luật `Enforce: forbid` thành luật Semgrep, đã kiểm chứng với Semgrep thật, để team đang chạy Semgrep thực thi decision trong CI ở quy mô lớn.

### Compatibility và giới hạn evidence

Không đổi schema, export, evidence package hay attestation hiện có. Release attestation ký các con số tại một commit; nó chứng minh ai ký con số nào, không chứng minh luật hay kiểm tra là đủ, và nó ký trạng thái thất bại một cách trung thực là `compliant: false` trừ khi bạn dùng `--require-compliant`. Khóa không bao giờ được tin từ chính file. `export-rules` chỉ xuất luật `forbid`: luật `require` và `require file` không biểu diễn được bằng Semgrep, và mọi luật bị bỏ qua đều được liệt kê trên stderr. Nhắc nhở của agent chỉ áp dụng cho sửa manifest dependency và ghi nguyên file hạ tầng, khớp tên theo từ nguyên, và không bao giờ duyệt proposal. `proofline mcp` không đổi: chỉ đọc và không xác thực caller.

## 日本語

### 出荷内容

- `proofline propose` は、承認済み decision が言及していない dependency やインフラのファイルに対する候補 decision を下書きします (`--base origin/main`、または `--kind`、`--name`、`--path`)。下書きは常に `Status: candidate` で、TODO の rationale と有効化されていない `Enforce:` ルール案を含み、代わりに承認されることはありません。Claude Code では `agent-hook post` が、agent がそのようなファイルを追加したときに通知し、下書きを提案するよう求めます。
- `proofline attest-release` は、`attest` と同じ Ed25519 鍵で、チェックアウト中の commit に対する内容を含まない声明に署名します: stale な citation 数、`Enforce:` の検出数、承認済み decision の digest、ledger の先頭、tracked ファイルの変更有無、`compliant`。`proofline verify-release-attestation` は信頼する鍵と、任意で commit に対して検証します。新しい `proofline-release-attestation-v1` schema であり、既存の attestation は変わりません。
- `proofline export-rules` は `Enforce: forbid` ルールを Semgrep ルールに変換します (実際の Semgrep で検証済み)。すでに Semgrep を使うチームは CI で decision を大規模に強制できます。

### Compatibility と限界

schema、export 形式、evidence package、既存の attestation に変更はありません。Release attestation は 1 つの commit における数値に署名するもので、誰がどの数値に署名したかを証明しますが、ルールや検査が十分かは証明しません。失敗状態も `--require-compliant` を指定しない限り `compliant: false` として正直に署名します。鍵はファイル自体からは決して信頼されません。`export-rules` は `forbid` のみを出力します。`require` と `require file` は Semgrep の一致では表現できず、スキップしたルールはすべて stderr に列挙されます。Agent の通知は dependency manifest の編集とインフラファイルの全体書き込みが対象で、名前は単語単位で照合し、proposal を承認することはありません。`proofline mcp` は変更なく、読み取り専用で caller を認証しません。
